## 2. Landasan Teori

### 2.1 Entity Relationship Diagram (ERD)
ERD adalah sebuah model konseptual yang digunakan untuk menggambarkan struktur data dan hubungan antar entitas dalam sebuah sistem basis data. ERD terdiri dari komponen:
- **Entitas (Entity)**: objek atau konsep yang datanya disimpan (contoh: `petugas`, `anggota`, `barang`).
- **Atribut (Attribute)**: properti atau karakteristik dari sebuah entitas.
- **Relasi (Relationship)**: hubungan antar dua entitas atau lebih, dengan kardinalitas 1:1, 1:N, atau M:N.

### 2.2 DDL (Data Definition Language)
DDL adalah bagian dari SQL yang digunakan untuk mendefinisikan struktur basis data, meliputi perintah:
- `CREATE DATABASE` – membuat database baru
- `CREATE TABLE` – membuat tabel baru beserta kolom dan constraint
- `ALTER TABLE` – mengubah struktur tabel
- `DROP TABLE` / `DROP DATABASE` – menghapus tabel atau database

### 2.3 Constraint MySQL
| Constraint | Fungsi |
|---|---|
| `PRIMARY KEY` | Kunci unik pengenal setiap baris |
| `FOREIGN KEY` | Menghubungkan dua tabel (referential integrity) |
| `NOT NULL` | Kolom wajib diisi |
| `AUTO_INCREMENT` | Nilai otomatis bertambah |
| `ENUM` | Membatasi nilai kolom pada pilihan tertentu |
| `DECIMAL(m,d)` | Tipe data bilangan desimal |

## 5. Implementasi DDL di phpMyAdmin

### 5.1 Script DDL

```sql
-- Membuat dan menggunakan database
CREATE DATABASE db_kopma;
USE db_kopma;

-- 1. Tabel Petugas
CREATE TABLE petugas (
    id_petugas    SMALLINT(6)                        NOT NULL AUTO_INCREMENT,
    kode_petugas  CHAR(3)                            NOT NULL,
    nama_petugas  VARCHAR(100)                       NOT NULL,
    peran_petugas ENUM('kasir','gudang','ketua')     NOT NULL,
    PRIMARY KEY (id_petugas)
);

-- 2. Tabel Anggota
CREATE TABLE anggota (
    id_anggota         INT(11)                    NOT NULL AUTO_INCREMENT,
    no_anggota         CHAR(6)                    NOT NULL,
    nim_anggota        CHAR(10)                   NOT NULL,
    nama_anggota       VARCHAR(100)               NOT NULL,
    prodi_anggota      VARCHAR(60)                NOT NULL,
    no_hp_anggota      VARCHAR(15)                NOT NULL,
    status_anggota     ENUM('aktif','nonaktif')   NOT NULL,
    tgl_daftar_anggota DATE                       NOT NULL,
    PRIMARY KEY (id_anggota)
);

-- 3. Tabel Barang
CREATE TABLE barang (
    id_barang         INT(11)                                    NOT NULL AUTO_INCREMENT,
    kode_barang       VARCHAR(10)                                NOT NULL,
    nama_barang       VARCHAR(100)                               NOT NULL,
    kategori_barang   ENUM('ATK','makanan','minuman','lainnya') NOT NULL,
    harga_jual_barang DECIMAL(12,2)                             NOT NULL,
    stok_barang       INT(11)                                    NOT NULL,
    stok_min_barang   INT(11)                                    NOT NULL,
    PRIMARY KEY (id_barang)
);

-- 4. Tabel Pemasok
CREATE TABLE pemasok (
    id_pemasok      INT(11)         NOT NULL AUTO_INCREMENT,
    nama_pemasok    VARCHAR(100)    NOT NULL,
    telepon_pemasok VARCHAR(15)     NOT NULL,
    alamat_pemasok  VARCHAR(200)    NOT NULL,
    PRIMARY KEY (id_pemasok)
);

-- 5. Tabel Penjualan
CREATE TABLE penjualan (
    id_penjualan      INT(11)         NOT NULL AUTO_INCREMENT,
    no_nota_penjualan CHAR(12)        NOT NULL,
    tgl_penjualan     DATETIME        NOT NULL,
    id_petugas        SMALLINT(6)     NOT NULL,
    id_anggota        INT(11)         NOT NULL,
    bayar_penjualan   DECIMAL(12,2)   NOT NULL,
    PRIMARY KEY (id_penjualan),
    FOREIGN KEY (id_petugas) REFERENCES petugas(id_petugas),
    FOREIGN KEY (id_anggota) REFERENCES anggota(id_anggota)
);

-- 6. Tabel Detail Penjualan
CREATE TABLE detail_penjualan (
    id_penjualan                  INT(11)         NOT NULL,
    id_barang                     INT(11)         NOT NULL,
    qty_detail_penjualan          SMALLINT(6)     NOT NULL,
    harga_satuan_detail_penjualan DECIMAL(12,2)   NOT NULL,
    FOREIGN KEY (id_penjualan) REFERENCES penjualan(id_penjualan),
    FOREIGN KEY (id_barang)    REFERENCES barang(id_barang)
);

-- 7. Tabel Pembelian
CREATE TABLE pembelian (
    id_pembelian        INT(11)                     NOT NULL AUTO_INCREMENT,
    no_faktur_pembelian VARCHAR(20)                 NOT NULL,
    tgl_pembelian       DATE                        NOT NULL,
    id_pemasok          INT(11)                     NOT NULL,
    status_pembelian    ENUM('dipesan','diterima')  NOT NULL,
    PRIMARY KEY (id_pembelian),
    FOREIGN KEY (id_pemasok) REFERENCES pemasok(id_pemasok)
);

-- 8. Tabel Detail Pembelian
CREATE TABLE detail_pembelian (
    id_pembelian                INT(11)         NOT NULL,
    id_barang                   INT(11)         NOT NULL,
    qty_detail_pembelian        INT(11)         NOT NULL,
    harga_beli_detail_pembelian DECIMAL(12,2)   NOT NULL,
    FOREIGN KEY (id_pembelian) REFERENCES pembelian(id_pembelian),
    FOREIGN KEY (id_barang)    REFERENCES barang(id_barang)
);
```

## 6. Analisis

### 6.1 Analisis Perancangan ERD

Basis data `db_kopma` dirancang untuk mendukung operasional **Koperasi Mahasiswa (KOPMA)** yang mencakup dua proses bisnis utama: **penjualan** kepada anggota dan **pembelian** dari pemasok.

**Struktur relasi yang terbentuk:**

| Relasi | Kardinalitas | Keterangan |
|--------|-------------|------------|
| `petugas` → `penjualan` | 1 : N | Satu petugas dapat melayani banyak transaksi penjualan |
| `anggota` → `penjualan` | 1 : N | Satu anggota dapat melakukan banyak transaksi penjualan |
| `penjualan` → `detail_penjualan` | 1 : N | Satu transaksi penjualan terdiri dari banyak detail barang |
| `barang` → `detail_penjualan` | 1 : N | Satu barang dapat muncul di banyak detail penjualan |
| `pemasok` → `pembelian` | 1 : N | Satu pemasok dapat dipilih untuk banyak transaksi pembelian |
| `pembelian` → `detail_pembelian` | 1 : N | Satu transaksi pembelian memuat banyak detail barang |
| `barang` → `detail_pembelian` | 1 : N | Satu barang dapat muncul di banyak detail pembelian |

> Seluruh relasi bersifat **One-to-Many (1:N)**. Tabel `detail_penjualan` dan `detail_pembelian` berfungsi sebagai **tabel bridge** yang memecah relasi Many-to-Many antara transaksi dan barang.

### 6.2 Analisis Implementasi DDL

**Keberhasilan implementasi:**
- ✅ Database `db_kopma` berhasil dibuat dan dipilih menggunakan `USE db_kopma`
- ✅ Seluruh 8 tabel berhasil dibuat dengan struktur kolom, tipe data, dan constraint yang sesuai rancangan ERD
- ✅ Urutan pembuatan tabel sudah benar: tabel induk dibuat sebelum tabel yang mereferensikannya
- ✅ Penggunaan `ENUM` yang tepat pada kolom `peran_petugas`, `status_anggota`, `kategori_barang`, dan `status_pembelian`
- ✅ Penggunaan `AUTO_INCREMENT` pada seluruh primary key surrogate (id)
- ✅ Pemilihan tipe data yang sesuai: `CHAR` untuk kode tetap, `VARCHAR` untuk nama variatif, `DECIMAL(12,2)` untuk nilai uang, `DATE`/`DATETIME` untuk waktu

**Kendala yang ditemukan:**
- ⚠️ Pada percobaan awal terdapat error **#1046 No database selected**, dikarenakan perintah `USE kopma` dijalankan sebelum database `db_kopma` dibuat. Solusinya: pastikan urutan `CREATE DATABASE db_kopma` → `USE db_kopma` → `CREATE TABLE`.
- ⚠️ Nama database sempat tidak konsisten (antara `kopma` dan `db_kopma`), menyebabkan error saat query dijalankan. Diselesaikan dengan menggunakan nama `db_kopma` secara konsisten di seluruh script.

### 6.3 Analisis Perbandingan Notasi ERD

| Aspek | draw.io (Physical) | MySQL Workbench (Crow's Foot) |
|-------|--------------------|-------------------------------|
| Notasi relasi | Garis panah sederhana | Crow's foot (standar industri) |
| Tampilan atribut | Tipe data & constraint lengkap | Tipe data MySQL |
| Keterbacaan | Mudah dipahami pemula | Lebih teknis, standar industri |
| Fitur | Manual, fleksibel | Dapat generate SQL otomatis |
| Warna relasi | Hitam polos | Warna berbeda per relasi |

Kedua tools menghasilkan rancangan yang **ekuivalen secara struktural**, namun MySQL Workbench lebih dekat ke implementasi teknis karena mendukung *forward engineering* (generate SQL DDL otomatis dari ERD).
